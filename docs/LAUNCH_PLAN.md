# Xcity Video Studio Launch Plan

_Issue: XCT-814. Owner: Studio fullstack. Date: 2026-09-01._

This plan turns the current Studio product surface into a release-ready demo and
beta launch. It is intentionally operational: timeline, feature checklist,
cross-project dependencies, and the first demo milestone.

## Launch Goal

Ship Studio as the Xcity AI creation workbench for video-first workflows:

- create multimedia content through TokenHub-backed Seedance and Seedream models;
- manage generated and uploaded assets across sessions;
- share, recreate, assemble, and export finished work without leaving Studio.

The launch is successful when a signed-in user can complete the creator loop
from prompt or reference asset to archived video, public share link, and reusable
history item on `studio.xcity.ai`.

## First Demo Milestone

**M1: Studio creator loop demo, target date 2026-09-08.**

The demo proves Studio is not just a generator; it is a persistent creation
workspace. Run it with a normal signed-in account and a launch-enabled TokenHub
key.

### Demo Script

1. Open Studio from the Xcity product entry point and confirm SSO provides the
   user's TokenHub key without manual paste.
2. Generate a 480p draft text-to-video clip with a visible estimated cost.
3. Add a stored image asset or named character as a reference, then generate a
   second clip using `[Image 1]` in the prompt.
4. Use **Extend** from a completed clip to create a continuation from the last
   frame.
5. Use **Finalize** on a draft, review the confirmation settings, and create the
   final-resolution version while keeping the source draft in history.
6. Show playback controls: fullscreen, direct download, and retry/archive state
   if the provider link is delayed.
7. Add the Xcity watermark, confirm the watermarked video is archived, and show
   original restore where available.
8. Create a share link, copy it, open the public page, and use recreate to hydrate
   Studio with the same prompt and params.
9. Select two completed clips from History, assemble them with a short BGM track,
   export MP4 plus SRT/FCP7 handoff, and replay the assembled output.

### M1 Acceptance

- One live account completes the full script without browser refresh recovery
  or developer-console intervention.
- Generated videos are available through R2 `storedUrl`, not only provider CDN
  links.
- History persists after signing in from a second browser profile.
- Billing and budget errors include a working route back to xct-home billing.
- Share/recreate works with a production media-worker URL and a prompt under the
  share limit.
- Any remaining launch blockers are written as explicit follow-up issues, not
  left as informal notes.

## Go/No-Go Checklist

- `NEXT_PUBLIC_OPENAI_API_BASE_URL` points at the production TokenHub gateway.
- `NEXT_PUBLIC_XCITY_SSO=true` and the xct-home key endpoint accepts Studio's
  production origin.
- `MEDIA_WORKER_URL` points at `https://media.xcity.ai` and `/api/config`
  reflects it after restart.
- TokenHub launch keys can access all enabled video/image/chat/audio models.
- Model price maps in Studio and TokenHub agree for launch-visible models.
- Failed and budget-exceeded tasks have user-facing copy and support escalation.
- Share/community moderation cannot publish unreviewed submissions.
- Production deploy has rollback instructions and release notes ready.
