# i18n Rules

Last updated: 2026-09-07

## Target

Use `next-intl` for `/zh` and `/en`.

Default locale:

- `zh`

Supported locales:

- `zh`
- `en`

## Routing

Target routes:

```text
/       -> default locale behavior, preferably /zh
/zh     -> Chinese Studio
/en     -> English Studio
/api/*  -> not localized
```

Share and media URLs should remain stable and should not require locale prefixes unless the page itself is a localized UI page.

## Flat English Keys (Required)

Follow the English-copy key strategy from `/Users/Vincent/2026/ledger-stack/apps/docs/rules/i18n.md`. The earlier Studio-specific semantic-namespace rule was an incorrect migration and is superseded by this section; it is not an allowed alternative.

- `src/i18n/messages/en.json` is the source of truth. Add English copy first, then update `zh.json` in the same change.
- Each dictionary is one flat JSON object of nonempty string values. No nested objects, arrays, duplicate JSON keys, or namespace aliases.
- The key is the normalized English copy, not a semantic identifier such as `apiKey.title` or `apiKey_title`. Let source directories express ownership, not dictionary namespaces.
- Both languages must have exactly the same keys. Chinese values, punctuation, and ICU placeholders remain localized content, not key material.
- Keep values unchanged when migrating keys. Normalize keys only; do not token-encode the displayed text or `{year}` inside values.
- Exact duplicate English copy may share one key only when its translations agree. Different originals that normalize to the same key are a hard conflict requiring an explicit copy decision. Do not silently overwrite or add numeric/business suffixes.
- Change all references together with the dictionaries. Do not retain dual legacy/new aliases or rebuild nested namespaces at runtime.

```json
{
  "Configure Xcity API Key": "Configure Xcity API Key",
  "You<apos>re in dry mode": "You're in dry mode",
  "Profit <lpar><pct><rpar>": "Profit (%)"
}
```

## Key Normalization

Use `scripts/harness/i18n/keys.ts` as the executable definition. Fixed order:

1. Normalize the English original to Unicode NFC.
2. Trim leading and trailing whitespace.
3. Strip leading and trailing periods (`.`), including an ending ellipsis.
4. Replace original characters with the tokens below in a single pass. Never tokenize newly generated `<...>` again.
5. Collapse consecutive whitespace to one ASCII space and trim any boundary spaces exposed by period removal.
6. Require a nonempty key containing only ASCII letters, digits, spaces, underscores, and recognized lowercase tokens. Unsupported characters fail; add a documented, tested mapping rather than silently removing them.

| Character | Token | Character | Token |
| --- | --- | --- | --- |
| `'` | `<apos>` | `"` | `<quot>` |
| `/` | `<slash>` | `%` | `<pct>` |
| `$` | `<usd>` | `(` | `<lpar>` |
| `)` | `<rpar>` | `{` | `<lcur>` |
| `}` | `<rcur>` | `[` | `<lbrk>` |
| `]` | `<rbrk>` | `:` | `<colon>` |
| `;` | `<semi>` | `,` | `<comma>` |
| `.` | `<dot>` | `&` | `<and>` |
| `+` | `<plus>` | `-` | `<dash>` |
| `?` | `<q>` | `!` | `<bang>` |
| `#` | `<hash>` | `@` | `<at>` |
| vertical bar (U+007C) | `<pipe>` | `<` | `<lt>` |
| `>` | `<gt>` | `=` | `<eq>` |
| `*` | `<star>` | `~` | `<tilde>` |
| backtick (U+0060) | `<btick>` | backslash (U+005C) | `<bslash>` |
| copyright (U+00A9) | `<copy>` | right arrow (U+2192) | `<rarr>` |
| em dash (U+2014) | `<mdash>` | ellipsis (U+2026) | `<hellip>` |

The final two rows are explicit Studio extensions for existing copyright, navigation, and playback-status copy. Values retain the original symbols. Example: `Saving...` uses key `Saving`; `Open xcity.ai.` uses `Open xcity<dot>ai`; copyright `{year}` in a key becomes `<copy> <lcur>year<rcur>`, while the value keeps the real symbol and ICU placeholder. U+2026 is a distinct character, encoded as `<hellip>` rather than stripped as an ASCII period.

## Translation Calls

Import `useTranslations` from `next-intl` or `getTranslations` from `next-intl/server` directly (named import aliases are supported). Bind the translator to a local constant and call it in that scope:

```tsx
const t = useTranslations();
t('Configure Xcity API Key');
t('Profit <lpar><pct><rpar>');

// Server Components may pass an explicit locale, but never a namespace.
const copy = await getTranslations({ locale });
copy('Save');
```

- `useTranslations('apiKey')`, `getTranslations('apiKey')`, and `namespace` options are forbidden. Use root translators only.
- Options must be explicit object literals, not variables, spreads, or computed properties that conceal a namespace. `createTranslator`, when needed, follows the same root-only policy.
- Every `t(...)`, `t.rich(...)`, `t.raw(...)`, `t.markup(...)`, and `t.has(...)` key must be a normalized string literal present in `en.json`. A template literal without interpolation is also static.
- Do not pass variables, concatenated strings, or interpolated templates as keys, even when TypeScript infers a literal union.
- Do not alias/destructure/pass translators to other functions, or wrap/re-export translation factories. Keep acquisition and calls locally auditable; helper functions may close over the local translator.
- Server `noteKey` / `messageKey` / `reasonKey` fields carry stable product codes, not translation keys. Resolve them through explicit `switch` branches or objects whose values call literal `t('...')`. Unknown codes use a safe readable fallback; never call `t(server.messageKey)`.

## Product UI Locale And Content Locale

There are two separate locale concerns:

| Concern | Meaning | Example |
| --- | --- | --- |
| UI locale | Language of Studio navigation, controls, errors, and system copy | /zh and /en |
| Content locale | Language of an Episode script, dialogue, subtitles, voiceover, and export | a Chinese source episode exported with English subtitles |

Do not use the UI route locale as the implicit language of a script, subtitle track, or dubbing result.

Episode content contracts should carry explicit sourceLocale, subtitleLocale, audioLocale, and targetLocale values where applicable.

## Content Localization Rule

- Keep the source script and every translated script version separately addressable.
- Keep subtitle tracks versioned and language-tagged.
- A dubbing or TTS track must declare its language and voice identity.
- Translation output is a draft until the user accepts it for an Episode Version.
- Never overwrite source-language dialogue, subtitle timing, or selected takes when generating a localized version.

## Migration Rule

Start with app shell strings before deep forms.

Suggested order:

1. navigation and tabs
2. API key gate/dialog
3. creation form
4. video output
5. history panel
6. assets/community
7. assembly editor
8. worker/share page copy if localized later

## Validation

Before shipping i18n changes, run `pnpm check:harness`, `pnpm test`, `pnpm typecheck`, `pnpm lint`, and `pnpm build`; inspect `/zh`, `/en`, and `/api/config` without paid generation.

The existing Quality CI runs the same Harness gate. `scripts/harness/inspect-i18n.ts` reports errors (nonzero exit), not advisories, for invalid/duplicate/nested dictionaries, mismatched language keys, noncanonical English keys, normalization collisions, missing literal keys, namespaces, and dynamic translation calls. The call check uses TypeScript syntax and local symbols, including import aliases and scope shadowing, not regex matches inside comments or strings.

`tests/harness/i18n-*.test.ts` contains rejection fixtures as well as valid cases. `tests/i18n/messages.test.ts` validates the actual flat dictionaries and formats every message through next-intl, including ICU interpolation. Existing deep-form hardcoded copy is tracked separately; this gate does not claim to detect every untranslated JSX string, assess translation quality, or prove server error semantics.

## Single Route Ownership

Keep each page implementation only under `src/app/[locale]`. Do not add duplicate unprefixed page wrappers for compatibility. `src/proxy.ts` uses next-intl middleware to redirect `/` to `/zh` and `/portrait-callback` to `/zh/portrait-callback`, preserving query parameters. When introducing another legacy page alias, add it to the proxy matcher and cover its redirect in routing tests. Keep API/media/static routes excluded; do not prefix provider URLs.

This follows the locale-normalization pattern in `/Users/Vincent/2026/ledger-stack/apps/web/middleware.ts`, adapted to Next.js 16's `proxy.ts` convention and Studio's existing endpoints. It does not copy that application's auth/session policy.

Place the translated shell and `NextIntlClientProvider` under the locale layout so navigation refreshes messages and server-rendered chrome. The shared root document sets the initial HTML language; the locale control synchronizes it after client navigation.
