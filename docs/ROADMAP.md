# Xcity Video Studio — 对齐世界顶级 AI 创作工作台的演进计划

_撰写于 2026-08-11，基于两轮竞品深度调研（生成能力层 + 工作台产品层，共 20+ 平台）。_
_前置：Roadmap 第 1–3 波已全部上线（续片/首尾帧/seed/运镜预设、分镜编写器/一键分镜/资产命名/参考音频、参考视频/成片组装）。_

## 战略定位

2026 年的市场分成三个阵营：

| 阵营 | 代表 | 特征 |
|---|---|---|
| 一键代工厂（agentic） | 即梦 AI片场、Hailuo Agent、OpenArt Story | 一句话成片，用户不掌控过程 |
| 节点流水线工作台 | Krea Nodes、Freepik Flow、Runway Dev | 专业用户搭 pipeline，学习成本高 |
| **叙事预演套件** | **LTX Studio、Google Flow** | 剧本→分镜→镜头→成片，创作者掌控每一步 |

我们的分镜编写器 + LLM 拆解 + 多模态参考已经站在**第三阵营**的门口。三个别人没有、
我们最容易建立的护城河：**云端持久化**（当前最大结构性短板）、**分享-复刻增长环**、
**诚实的真实成本 UX**（全行业用积分制掩盖成本，我们直接显示美元——保持并放大它）。

已达到或超过中档竞品的部分：多模态参考输入（图+音+视频，强于多数西方工具）、
30s/4K Seedance 通道、带 LLM 拆解的分镜（LTX 同类核心）、真实成本核算。

## 差距矩阵（工作台层）

| 维度 | 状态 | 缺口 |
|---|---|---|
| 项目/组织 | ⚠️ 部分 | 历史/设置仅存 localStorage——**换浏览器即丢失全部工作室**；无项目/标签/多设备 |
| 编辑套件 | ⚠️ 薄 | 只有拼接；无剪切/变速/字幕/TTS/BGM/转场/超分 |
| 角色/风格持久化 | ⚠️ 部分 | 参考图是一次性的；无跨镜头命名角色（Flow Ingredients / Kling Elements 式） |
| 发布分发 | ❌ 缺失 | 无平台预设导出、无 NLE 交接、无公开分享页 |
| 协作 | ❌ 缺失 | 单用户（暂缓，per-key 计费未来是好的团队原语） |
| 自动化 | ⚠️ 部分 | 有分镜拆解；无批量/变量生成、无用户 API 配方 |
| 移动端 | ❌ 缺失 | 无 PWA/响应式 |
| 可靠性 UX | ⚠️ 部分 | 有成本核算；无草稿档、无提交前精确报价、失败退款不透明 |

## 演进计划（按价值排序；同档按投入从低到高）

### 第四波 — 基座：云端持久化与信任（最高优先）

| # | 功能 | 价值 | 投入 | 方案要点 |
|---|---|---|---|---|
| 1 | **云端同步的历史与设置** | ⭐⭐⭐⭐⭐ | 中 (+worker) | 结构性最大短板。R2 已在手：`u/<user_id>/state/history.json`（ETag 乐观并发），worker 加 GET/PUT `/state`；localStorage 降级为缓存。不引入新存储（KV/D1 都不需要） |
| 2 | **草稿→成片生成阶梯** | ⭐⭐⭐⭐ | 低 (纯前端) | 行业标准迭代经济学（Kling Turbo/Hailuo Fast）。新 prompt 默认 480p/短时长草稿档，"以最终画质重跑"一键携带 seed+全部设置。1.5 Pro 的 `draft` 参数（$0.06 预览）后续接入 |
| 3 | **提交前精确报价 + 失败不计费透明化** | ⭐⭐⭐⭐ | 低-中 (+gateway 核验) | 我们收真钱。提交按钮旁显示精确美元；失败任务在历史中标注"未计费"（需核验 LiteLLM 对失败任务的计费行为）。Kling 最大用户抱怨就是积分被吞——信任即功能 |

### 第五波 — 增长飞轮

| # | 功能 | 价值 | 投入 | 方案要点 |
|---|---|---|---|---|
| 4 | **公开分享页 + 一键复刻** | ⭐⭐⭐⭐⭐ | 中 (+worker) | 媒体已在 R2；worker 出 `/share/<id>` HTML 页（视频 + prompt + 参数 + "在 Studio 复刻"深链预填表单）。对标 Flow TV / Kling feed 的获客环；现有 Gallery 升级为其特例 |
| 5 | **命名角色/元素（Ingredients）** | ⭐⭐⭐⭐ | 低-中 (纯前端) | 资产库图片"升格为角色"（命名），分镜/表单里以 chips 一键挂载到参考位并注入 `[Image N]` 引用。建立在已有多参考管线上，Flow Ingredients 的 UX 而非 Soul-ID 式训练 |
| 6 | **作品广场（分享-复刻型社区）** | ⭐⭐⭐⭐ | 中 (+worker) | 已评估批准（2026-08-11）。严格限定"创作展示+复刻"形态，不做消费型社交 feed（Sora 死因）。三期：**V1 先审后发**——"分享到广场"→ 人工审核队列 → 广场 tab（视频+prompt+参数+昵称+一键复刻），R2 公共命名空间 `community/<id>`，worker 加 publish/list/review 端点；**V2** 视觉模型自动初审（走自家网关）+ 举报下架 + 点赞排序；**V3** 高赞作品变量化=模板库。成本结构优势：R2 零出站费、无推理成本；硬门槛是审核责任，先审后发压到可控。不做评论/关注/私信 |
| 7 | 模板库（带变量的分享页） | ⭐⭐⭐ | 中 | 从广场 V3 自然生长：高赞作品 + 可替换变量=模板。PixVerse 的 500 模板证明这是获客主环 |

### 第六波 — 成片能力（对标 CapCut 的 80/20）

| # | 功能 | 价值 | 投入 | 方案要点 |
|---|---|---|---|---|
| 7 | **Timeline v2：剪切/排序/BGM/转场** | ⭐⭐⭐⭐ | 中-高 (纯前端) | 组装器从 concat 升级为最小真剪辑：每段入出点、资产库 BGM 音轨混入、交叉溶解（需重编码路径，wasm 慢——限制在导出时提示时长）。MVP 先做 trim+BGM，转场次之 |
| 8 | **自动字幕 + TTS 配音** | ⭐⭐⭐⭐ | 中 (+gateway 配模型) | 走既有网关：Whisper 类转写 + TTS（LiteLLM 原生支持 /audio/*，tokenhub 需配置模型）；ffmpeg.wasm 烧字幕或 sidecar srt。对比 CapCut 的最大单点差距 |
| 9 | **平台导出预设 + NLE 交接** | ⭐⭐⭐ | 低-中 (纯前端) | ffmpeg.wasm 裁切 9:16/1:1/16:9 + 码率预设（抖音/Reels/Shorts）；分镜时间线导出 FCP7-XML/EDL 引用 R2 地址（LTX 最受专业用户欢迎的功能，本质是字符串模板） |

### 第七波 — 规模化

| # | 功能 | 价值 | 投入 | 方案要点 |
|---|---|---|---|---|
| 10 | **批量/变量生成** | ⭐⭐⭐ | 低-中 (纯前端) | prompt × seed × ratio 矩阵；"渲染全部分镜"队列（use-video-jobs 已支持多任务，加并发上限）。机构用户为此付费给 Krea/Freepik |
| 11 | **PWA + 移动布局** | ⭐⭐⭐ | 中 | manifest + 响应式分镜/历史。头部玩家全部在手机上；PWA 是单人团队规模的答案 |
| 12 | 用户 API 配方文档 | ⭐⭐ | 低 | 用户本来就持有 TokenHub key——把 /v1/videos 直调配方写成文档页即是免费营销 |

### 明确暂缓（论证过，不做）

- **协作/评论/团队空间**：新基建投入大，在有团队用户前 ROI 低（广场也不做评论——审核负担重）；
- **Soul-ID 式可训练角色**：依赖 provider 能力（Ark 数字角色库 API 面不全）；
- **消费型社交 feed（关注/推荐流/私信）**：Sora feed 关停的前车之鉴；作品广场只保留
  "展示+复刻"这一创作侧价值，社交机制全部砍掉。

## 执行方式

沿用第 1–3 波的模式：Codex（GPT-5.5 xhigh）实现，Claude 出任务书/审 diff/浏览器验证/合并。
每波独立可发布；第四波 #1 是其余一切的前提（分享、模板、批量都受益于云端状态）。

## 风险与依赖

- #1 并发写：ETag If-Match 乐观锁，冲突时以服务端为准提示刷新（单用户多设备，冲突罕见）;
- #3 需先核验 LiteLLM 失败任务计费行为（一次网关日志检查）;
- #7 转场需重编码，wasm 性能是硬约束——先 trim/BGM（流复制或仅音轨编码），转场设预期;
- #8 依赖 tokenhub 配置 whisper/tts 模型（网关代码已支持，纯配置）。
